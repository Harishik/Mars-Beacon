# Submission checklist

Based on the supplied seven-page Team NASHA Seoul guide. The latest official NASA submission guide takes priority for project rules; Seoul guidance governs local attendance. Checklist entries are deliberately not pre-attested.

## Prepared in this documentation update

- [x] Live website and direct mission-map links at the top of the README.
- [x] Current implementation, architecture, setup and limits documented.
- [x] Claude Code, Codex and Microsoft TRELLIS.2 disclosed.
- [x] Source/product register, dependency inventory and asset-attribution records added.
- [x] English summary draft within 50–200 words and form-text backup prepared.
- [x] Demo-video and walkthrough-video locations reserved without media content.

## Remaining before submission

- [ ] Provide one public official demo: <=30-second video OR <=7-slide deck (title included). Both requested video folders are intentionally unfilled.
- [ ] Add the optional walkthrough only when ready; do not substitute it for the length-limited demo.
- [ ] Match at least one used NASA source to the selected challenge's official Resources list.
- [ ] Resolve the specific source/licence/input-provenance gaps in REFERENCES.md and ASSET_CREDITS.csv.
- [ ] Inspect generated assets for prohibited NASA branding and add visible generation labels to all submitted images and generated video portions; review the deployed presentation too.
- [ ] Review AI disclosure scope and generated-asset per-file mapping with the team.
- [ ] Complete actual form fields, including NASA/partner/other-resource fields, with consistent attribution.
- [ ] Test every submitted link logged out on multiple devices; ensure no login, password, registration or permission prompt. Public site/repository were checked in one environment only.
- [ ] Check submitted images are JPG/PNG/GIF and <=10 MB each; host videos/documents externally.
- [ ] Check no confidential material, credentials or identifiable names/voices/images of under-18s are published. Existing repository history and every binary asset have not been exhaustively audited in this documentation pass.
- [ ] Confirm all team members are on the official team page for the same Seoul event.
- [ ] Review current service health and keep stale/unavailable feed labels truthful.

## Team Owner action

- [ ] Click **Submit for Judging** before **15 November 2026, 23:59 KST**; aim for 23:55 or earlier.
- [ ] Verify **Project Submitted for Judging** and save evidence privately.
